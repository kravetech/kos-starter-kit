# Security Policy

## Supported Version

Security fixes are applied to the latest release on the `main` branch.

## Reporting a Vulnerability

Do not open a public issue for a suspected vulnerability, privacy leak, or exposed credential.

Use GitHub private vulnerability reporting when enabled. Include:

- affected version or commit;
- reproduction steps;
- security or privacy impact;
- any suggested remediation.

Do not include live credentials, personal records, or client data. Revoke or rotate any exposed credential before reporting it.

## Scope

Security-sensitive areas include installer target containment, migration backups, overwrite behavior, generated Git exclusions, template expansion, privacy scanning, and agent-launcher command construction.
